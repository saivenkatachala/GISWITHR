Chapter 1›Introduction to R
1.1 Introduction

Introduction to R

R was originally created by statisticians for statistical computing, but has grown into one of the most powerful programming languages for data analysis.

Key Application Areas

📊
Data Science & ML
Predictive modeling, clustering, and data mining workflows.
💹
Finance & Economics
Stock market forecasting, risk analysis, and econometrics.
🧬
Bioinformatics
Genomic data analysis, epidemiology, and clinical trials.
🌐
Web Dashboards
Tools like Shiny allow building interactive web apps from R.
🎓
Academia & Research
Gold standard for publishing reproducible scientific research.

Key Features of R

  • Open-source — Free to use and modify
  • Statistical capabilities — Supports advanced statistical modeling
  • Data visualization — Integrated tools like ggplot2 for high-quality graphics
  • Integration — Works with Python, C, C++, Java, and SQL
💡 Note
R is both a programming language AND an environment with tools for data handling, calculation, and graphical display.
Chapter 1›R in Geospatial Technology
1.2 Geospatial

R in Geospatial Technology

In R, almost everything — numbers, tables, plots, and even maps — is treated as an object, making data handling very flexible.

Why Use R for GIS?

🔁
Reproducibility
If you get updated LULC data, just re-run your script. No re-clicking required.
⚙️
Automation
Loop through and process hundreds of satellite images or shapefiles at once.
📐
Advanced Statistics
Seamlessly combine spatial data with advanced statistical modeling.

R's Role in Geospatial

R provides thousands of pre-built packages for performing advanced tasks such as machine learning, time-series analysis, and geospatial analysis without writing complex code from scratch.

✅ Best for
Researchers and analysts who need to combine spatial data processing with statistical modeling and visualization in a single reproducible workflow.

1.3 Data Types

Data Types & Structures

Understanding how R stores data is the first step to mastering it.

Basic Data Types

TypeDescriptionExample
NumericNumbers with decimals17.5, 44
IntegerWhole numbers (suffix L)10L
CharacterText / strings"Hyderabad"

R — Data Types Example
# Assigning different data types
num  <- 45.5
text <- "R Language"
flag <- TRUE

# Checking types
class(num)   # "numeric"
class(text)  # "character"
class(flag)  # "logical"

Data Structures

Vector — 1D Sequence

A one-dimensional sequence of elements of the same data type.

R — Vectors
# A character vector of Telangana districts
districts <- c("Hyderabad", "Medak", "Adilabad", "Warangal")

# A numeric vector representing land area in sq km
area_sqkm <- c(217, 2740, 4153, 1975)

Matrix — 2D Grid

A two-dimensional grid where all elements must be of the same data type.

R — Matrix
# Creating a 3x3 matrix of elevation values
elevation_values <- matrix(
  c(500, 520, 510,
    490, 480, 505,
    515, 530, 525),
  nrow = 3, ncol = 3
)

Data Frame — The Powerhouse

A 2D table where each column can be a different data type. Similar to a SQL table or Excel file.

R — Data Frame
telangana_data <- data.frame(
  District        = c("Hyderabad", "Medak", "Adilabad"),
  Area_SqKm       = c(217, 2740, 4153),
  Is_Urban_Center = c(TRUE, FALSE, FALSE)
)

List — Most Flexible

Can hold any combination of structures: vectors, matrices, data frames.

R — List
my_project_data <- list(
  study_areas    = districts,         # A vector
  elevation_grid = elevation_values,   # A matrix
  demographics   = telangana_data      # A data frame
)
Chapter 1›Basic R Syntax
1.4 Syntax

Basic R Syntax

R follows a simple and readable syntax. Commands are executed line by line.

Core Syntax Rules

  • Use <- as the assignment operator to store values in variables
  • R is case-sensitive — Data and data are different objects
  • Comments begin with # and are ignored during execution
  • Variables do not need explicit type declaration
R — Basic Syntax
# Assigning a value to a variable
population <- 3500000

# Simple arithmetic
total_area <- 500 + 250

# Printing a variable
print(population)

# String concatenation
paste("City:", "Hyderabad")
📌 Key Note
R is an interpreted language — it reads and executes code line-by-line rather than compiling all at once.

Chapter 2›Vector Data Visualization
2.1 Vector Visualization

Vector Data Creation & Visualization

Vector data represents the world using discrete geometry: points, lines, and polygons.

Geometry Types

📍
Points
A single X,Y coordinate. E.g., location of a KGBV school or temple.
〰️
Lines
A connected series of points. E.g., path of National Highway 44.
⬡
Polygons
A closed shape representing an area. E.g., district boundary.
R — Creating Vector Geometries
library(sf)

# 1. Create a Point (Hyderabad coordinates)
hyd_point <- st_point(c(78.4867, 17.3850))

# 2. Create a Line (simplified NH44 segment)
nh44_coords <- matrix(c(78.40, 17.30,
                        78.45, 17.50,
                        78.55, 17.80), ncol=2, byrow=TRUE)
nh44_line <- st_linestring(nh44_coords)

# 3. Create a Polygon (must close the loop!)
boundary_coords <- matrix(c(78.0,17.0, 79.0,17.0, 79.0,18.0,
                            78.0,18.0, 78.0,17.0), ncol=2, byrow=TRUE)
district_poly <- st_polygon(list(boundary_coords))

# Plotting all geometries together
plot(district_poly, col="lightgrey", main="Vector Geometries")
plot(nh44_line,    col="blue",      lwd=2,  add=TRUE)
plot(hyd_point,   col="red",       pch=16, add=TRUE)
Chapter 2›Thematic Mapping
2.2 Thematic Mapping

Thematic Mapping

Instead of just showing where things are, thematic maps show what is happening there.

Choropleth Maps

Uses color shading inside polygons (districts, mandals) to represent a statistical value. Low numbers = light color, high numbers = dark color.

R — Choropleth Map
library(sf)
library(ggplot2)

telangana_districts <- st_read("TS_DISTRICTS_UTM.shp")

ggplot(data = telangana_districts) +
  geom_sf(aes(fill = area), color="black", linewidth=0.2) +
  scale_fill_viridis_c(name="District Area", option="magma") +
  labs(title="Size of Telangana Districts",
       subtitle="Choropleth Map based on Geographic Area") +
  theme_minimal()

Heat Maps (KDE)

Kernel Density Estimation — creates a smooth, continuous surface showing where points are concentrated. Useful for finding "hotspots".

R — Heat Map / KDE
library(sf); library(ggplot2)

temples_sf <- st_as_sf(temples_df,
  coords=c("Longitude","Latitude"), crs=4326)
coords <- as.data.frame(st_coordinates(temples_sf))

ggplot() +
  geom_sf(data=districts_sf, fill="#f0f0f0", color="white") +
  stat_density_2d(data=coords,
    aes(x=X, y=Y, fill=after_stat(level)),
    geom="polygon", bins=25, alpha=0.6) +
  scale_fill_gradientn(
    colors=c("blue","green","yellow","orange","red"),
    name="Temple Density")

Spatial Clustering (K-Means)

Groups locations into clusters using mathematical algorithms. Useful for dividing villages into zones or assigning regional managers.

💡 Algorithm
You tell the computer how many clusters you want (e.g., k = 5). K-means groups points so that points in the same cluster are as close to each other as possible.
Chapter 2›CRS & Projections
2.3 CRS

CRS, Georeferencing & Projections

A CRS tells the computer how a 2D map relates to the real, 3D Earth.

Types of CRS

🌍
Geographic CRS
Uses degrees (Longitude/Latitude). Example: WGS 84 (EPSG: 4326). Good for global locations.
📏
Projected CRS
Uses linear units (meters/feet). Flattens the earth to calculate accurate distances. Example: UTM zones.

Common EPSG Codes for India

EPSGNameTypeBest Used For
4326WGS84Geographic (degrees)Global maps, GPS, web mapping
32643UTM Zone 43NProjected (meters)Western India (Gujarat, Rajasthan)
32644UTM Zone 44NProjected (meters)Central India (Hyderabad, Nagpur)
32645UTM Zone 45NProjected (meters)Eastern India (Kolkata, Odisha)
3857Web MercatorProjected (meters)Google Maps, OpenStreetMap tiles
R — CRS Transformation
# Transform data to a different projection
data_projected <- st_transform(data, crs=3857)

# Check current CRS
st_crs(data)

# Overlaying multiple layers — ensure same CRS!
highway_layer <- st_transform(highway_layer, st_crs(districts_layer))
temples_layer <- st_transform(temples_layer, st_crs(districts_layer))
⚠️ Warning
When overlaying multiple layers, always ensure they are in the SAME CRS. Mismatched projections are a very common source of errors in GIS analysis.
Chapter 2›Raster Data Visualization
2.4 Raster

Raster Data Visualization

Raster data stores geographic information as a regular grid of cells, like a digital image where each pixel has a value.

Raster Structure Concepts

  • Pixels/Cells: Each pixel holds exactly one numeric value (elevation, temperature, reflectance)
  • High Resolution: Small pixels (1 pixel = 1 meter) — fine detail, more memory
  • Low Resolution: Large pixels (1 pixel = 1 km) — good for large areas, less detail
  • Spatial Resolution: For Landsat imagery, this is 30m × 30m per pixel
R — Single Band Raster Display
library(terra)

# Load a single band from Landsat
band <- rast("LT05_L1TP_143047_20051110_B1.TIF")

# Display with grayscale palette
plot(band, col=gray.colors(256))

Satellite Imagery — Multi-band

R — Multi-band Landsat
# Stack multiple bands
bands <- c("B1.TIF","B2.TIF","B3.TIF","B4.TIF")
landsat_data <- rast(bands)
names(landsat_data) <- c("Blue","Green","Red","NIR")

# True Color Composite (RGB)
plotRGB(landsat_data, r=3, g=2, b=1)

# False Color (NIR, Red, Green) — vegetation appears RED
plotRGB(landsat_data, r=4, g=3, b=2, stretch="lin",
        main="False Color Composite")

DEM — Digital Elevation Model

R — 3D DEM with rayshader
library(terra); library(rayshader)

dem <- rast("BCM_DEM.tif")
dem[is.na(dem)] <- 0

el_matrix <- raster_to_matrix(dem)

el_matrix %>%
  sphere_shade(texture="desert") %>%
  add_shadow(ray_shade(el_matrix, zscale=33), 0.5) %>%
  plot_3d(el_matrix, zscale=10, fov=0, theta=135, zoom=0.75, phi=45)
Chapter 2›Spectral Bands & NDVI
2.5 Spectral Analysis

Spectral Bands & NDVI

Satellites capture light beyond what the human eye can see — these are stored as separate bands.

Landsat Band Overview

BandNameUse Case
Band 1BlueWater body analysis
Band 2GreenVegetation greenness
Band 3RedChlorophyll absorption
Band 4Near-Infrared (NIR)Vegetation health — plants reflect NIR intensely

NDVI — Vegetation Index

NDVI (Normalized Difference Vegetation Index) measures plant health using the formula:

🌿 NDVI Formula
NDVI = (Band4 − Band3) / (Band4 + Band3)
Values range from -1 to +1. Higher positive values = denser, healthier vegetation.
R — NDVI Calculation
library(terra)

band3 <- rast("LT05_B3.TIF")   # Red
band4 <- rast("LT05_B4.TIF")   # Near-Infrared

# Calculate NDVI
ndvi <- (band4 - band3) / (band4 + band3)

# Apply vegetation color palette
color_palette <- colorRampPalette(
  c("blue","orange","yellow","lightgreen","darkgreen")
)(100)

plot(ndvi, col=color_palette, main="NDVI Map")

# Save the output
writeRaster(ndvi, "Landsat5_NDVI.tif", overwrite=TRUE)
Chapter 3›Querying & Selection
3.1 Querying

Querying & Spatial Selection

Querying is the process of extracting specific features from a dataset based on conditions.

Attribute-Based Query

Filter features based on their attribute values (like SQL WHERE clauses).

R — Attribute Query
library(sf); library(ggplot2)

districts <- st_read("TS_DISTRICTS_UTM.shp")

# Select districts with area less than 2000 sq km
small_districts <- districts[districts$area < 2000, ]

ggplot() +
  geom_sf(data=districts,      fill="white") +
  geom_sf(data=small_districts, fill="pink", color="black") +
  labs(title="Districts with Area < 2000")

Spatial Selection (Multi-Layer)

Select features from one layer based on their spatial relationship with features in another layer.

R — Spatial Selection
library(terra)

districts <- vect("TS_DISTRICTS_UTM.shp")
road      <- vect("NH44.shp")

# Ensure same CRS
if (crs(districts) != crs(road)) {
  road <- project(road, districts)
}

# Find districts that intersect the highway
intersects_logic    <- relate(districts, road, "intersects")
intersecting_districts <- districts[as.vector(intersects_logic), ]

plot(districts, col="lightgray", main="Districts Intersecting NH44")
plot(intersecting_districts, col="red", add=TRUE)
plot(road, col="yellow", lwd=2, add=TRUE)
Chapter 3›Geo Processing Tools
3.2 Geo Processing

Geo Processing Tools

Core spatial analysis operations: Buffer, Dissolve, Merge, Union, Clip, and Intersection.

1. Buffer Creation

Generating zones of a specified distance around geographic features.

📍
Point Buffer
Creates a circle around a point (e.g., 500m around a hospital).
〰️
Line Buffer
Creates a corridor along a line (e.g., 1km either side of a road).
⬡
Polygon Buffer
Expands or shrinks a polygon (e.g., buffer around a lake).
R — Buffer Operations
library(sf); library(ggplot2)

mandals <- st_read("Adi_mandals.shp") %>% st_transform(32644)
canal   <- st_read("canal.shp") %>% st_transform(32644)

# Polygon Buffer — 2km around specific mandals
mandals_list     <- c("UTNOOR","TAMSI","NERADIGONDA")
multiple_mandals <- mandals[mandals$Sub_dist %in% mandals_list, ]
multiple_buffers <- st_buffer(multiple_mandals, dist=2000)

# Line Buffer — 2km along canal
canal_buffer <- st_buffer(canal, dist=2000)

2. Dissolve

Removes internal boundaries between features that share a common attribute. E.g., dissolving districts into zones.

R — Dissolve
library(sf); library(dplyr)

villages <- st_read("Adi_rev.shp")

# Dissolve villages into mandals by Sub_dist attribute
mandals <- villages %>%
  group_by(Sub_dist) %>%
  summarize(geometry = st_union(geometry))

st_write(mandals, "Adi_mandals.shp")

3. Merge vs Dissolve

OperationWhat it doesSQL Equivalent
MergeCombines multiple layers into one. All features retained. No boundary removal.UNION ALL
DissolveFuses features within one layer based on shared attribute. Boundaries erased.GROUP BY

4. Clip & Intersection

OperationAttributes KeptDescription
ClipFrom input layer onlyCuts input layer to the boundary of clip layer
IntersectionFrom BOTH layersKeeps only overlapping portions with attributes from both
R — Intersection
library(sf)

villages     <- st_read("Adi_rev.shp") %>% st_transform(32644)
canal_buffer <- st_read("canal_buffer.shp") %>% st_transform(32644)

# Intersection keeps attributes from BOTH layers
canal_intersect <- st_intersection(canal_buffer, villages)

st_write(canal_intersect, "canal_intersect.shp", delete_layer=TRUE)
